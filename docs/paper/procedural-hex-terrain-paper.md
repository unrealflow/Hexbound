# 六边形网格上的程序化地形生成：数据原理与工程实现

——以 Hexbound（WebGL / Babylon.js 六边形策略地图）为例

> 版本：2026-09-19。本文对应仓库当前工作区实现（`src/hex/*`、`src/render/*`），
> 全部公式与常数均取自真实代码；文末验证一节的所有指标为本轮实测输出。
> 配套阅读：`docs/design/hexbound-terrain-maturity-spec.md`（验收规格）、
> `docs/design/impl-progress.md`（迭代日志）、`docs/VISUAL_TARGETS.md`（视觉基准）。

## 摘要

Hexbound 在浏览器内以单次 CPU 生成 + GPU 着色的方式，产出一块 40×32 的六边形
策略地图，目标观感为《文明》/《Humankind》式的"连续有机地形，但保留六边形游玩
语义"。整个系统的核心矛盾是：**游玩语义要求世界按整格离散（一个格子一个地形
类型、一个可点击单元），而视觉质感要求场连续（没有六边形马赛克、没有裙边裂缝）**。
本文以"数据原理"为主线完整拆解该系统：

1. **场的合成**——以带解析导数的分形值噪声（FBM）、脊线噪声（Ridged FBM）与
   域扭曲（Domain Warping）在 axial 格网上合成连续标量场（大陆、高度、湿度、
   森林覆盖），并用六边形 BFS 距离场完成岸线缓坡与河谷雕刻；
2. **数据的表示**——把"每格一个标量"的零阶保持信号，经 4×4 子格重采样与
   `(1−d/r)³` 紧支撑核卷积预滤波后打包进两张 RGBA8 数据纹理；岸线以**精确的
   有符号线段距离场（SDF）**烘焙，替代逐格水位标志；
3. **几何的焊接**——顶面扇形的角点高度无条件焊接为"共享该角点的格集合均值"，
   同一世界角点在全图只有一个高度，网格水密且**任何平面切面都是连续曲线**
   （不存在垂直墙与台阶；陡峭地形以连续陡坡表达）；
4. **GPU 的一致性**——顶点位移的全部输入要么是按世界位置查询的 welded 标量，
   要么是"仅依赖世界位置"的门控 `dispW`，从而同一世界位置的每个顶点拷贝位移
   一致（2557 个共享位置实测 0 撕裂）；
5. **验证方法学**——以五个可复现的门禁（`crack / corner / hole / disp:weld /
   pick`）把"无缝"从主观判断变为可测不变式。

关键词：程序化地形生成；六边形网格；分形布朗运动；域扭曲；距离场；数据纹理；
预滤波；焊接网格；水密性；WebGL

## 1 引言

### 1.1 问题设定

六边形策略地图（Civ 系列、Humankind）的视觉基准有两个看似冲突的特征：

- **宏观连续**：山脉是连绵的褶皱山脊而非一摞六棱柱；海岸是沙滩→浅海→深海的
  连续色带而非锯齿阶梯；森林是有机团块而非整格色块。
- **微观离散**：地图仍由六边形组成——拾取按格、高亮按格、边界沿格。

此外项目后来追加了一条**硬约束（地形连续性规格）**：*用任意竖直平面切过地形，
得到的剖面必须是连续且平滑的曲线——不允许任何形式的高度突变*。这条规格直接
否决了早期"崖墙/台地"机制（垂直墙面 = 剖面上的无穷坡度 = 跳变），本系统因此
收敛为"全焊接连续高度场"方案（§5.2）。它同时把 C¹ 意义下的"平滑"也纳入考量：
场由多尺度的平滑算子构成（格间均值、连续位移、片元解析法线），不引入任何逐格
硬边界。

离散"游玩格"与连续"观感场"之间的张力，本质上是**信号处理问题**：游玩数据是
定义在六边形格点上的逐格常数（零阶保持），而任何直接渲染逐格常数的方法都会把
六边形轮廓画进画面（等值线必然沿格边）。Hexbound 的全部设计都围绕一个问题展开：
**在哪里、以什么算子，把离散数据变换成连续场，同时不破坏游玩语义与水密几何。**

### 1.2 总体管线

```
generateMap (CPU, 一次性)                      meshMap (CPU)              GPU 每帧
┌──────────────────────────────┐   ┌────────────────────────┐   ┌──────────────────┐
│ 1) FBM/脊线/域扭曲 → 连续场   │   │ 焊接角点高度 (cellTopY) │   │ vert: 位移(权重×  │
│ 2) BFS 岸距 → 缓坡/水深       │ → │ 顶面扇形（全焊接,无墙） │ → │   dispW 门控)     │
│ 3) 阈值分类 → terrainId       │   │ 逐顶点 welded 属性      │   │ frag: 数据纹理    │
│ 4) 河谷雕刻 + 距离场          │   │ (elev/mtnW/forestW/…)   │   │   双线性 1 tap    │
│ 5) 打包两张 RGBA8 (4×4 子格)  │   │ 分 chunk (8×8)          │   │   解析法线/光照/雾 │
└──────────────────────────────┘   └────────────────────────┘   └──────────────────┘
        HexMap.ts / mapgen.ts            ChunkMesher.ts /            hexTerrain.{vert,frag}
        terrainContinuity.ts             HexTerrainMaterial.ts       + noise.glsl
```

## 2 坐标与距离：六边形格网上的度量

### 2.1 Pointy-top axial 坐标

采用尖顶（pointy-top）axial 坐标 `(q, r)`，第三轴满足 `s = −q − r`。
格心世界坐标（`HEX_SIZE = 1`，`src/hex/coords.ts`）：

```
x = √3 · (q + r/2)          q = (√3/3 · x − 1/3 · z)
z = (3/2) · r        ⟺      r = (2/3) · z
```

这是一个线性双射，因此**世界域上的连续噪声可以直接采样，再在需要"格语义"
（拾取、邻接）时用 cube-round 取整**：

```
cube-round：s = −q−r；对 (q, r, s) 分别四舍五入为 rq, rr, rs；
若 |rq−q| 最大则 rq = −rr−rs，否则若 |rr−r| 最大则 rr = −rq−rs。
```

### 2.2 两种距离，两种用途

| 距离 | 定义 | 复杂度 | 用途 |
|------|------|--------|------|
| Hex 距离 | `(|dq| + |dq+dr| + |dr|)/2` 或 BFS 环计数 | O(1) / O(N) | 邻接语义、缓坡带宽 |
| 欧氏世界距离 | `√(Δx² + Δz²)`，或线段 SDF | O(N)（本图规模暴力即可） | 水深、岸带宽度 |

早期版本曾把水深做成 BFS 环计数（0..8 整数环），渲染上立刻出现**六边形深度
阶梯**——这是"离散环距离"与"连续视觉梯度"不匹配的直接证据，随后被连续欧氏
距离替换（`HexMap.recomputeShoreDepth`）。这个教训贯穿全文：**凡是进入渲染的
量必须是连续场；离散量只允许停留在游玩语义层。**

## 3 场的合成：从噪声到地形

### 3.1 值噪声与解析导数

基础原子是 **quintic 插值的值噪声**（`noise.glsl: noised`）。格点哈希：

```
hash21(p)：p₃ = fract(p.xyx · 0.1031)
          p₃ += dot(p₃, p₃.yzx + 33.33)
          return fract((p₃.x + p₃.y) · p₃.z)
```

单元内以 quintic 权 `u(t) = t³(t(6t−15)+10)` 双线性混合四个格点哈希。选 quintic
而非 cubic（`3t²−2t³`）的原因有二：其一，quintic 是 **C² 连续**的，其二阶导在格
点处为 0，法线不会在格边界出现折痕；其二，解析导数形式干净：

```
u'(t) = 30 t² (t−1)²      （即 fade2d）
∂n/∂x = u'(fx) · (k₁ + k₃·u(fy))，  ∂n/∂z 同理对称
其中 k₀=a, k₁=b−a, k₂=c−a, k₃=a−b−c+d 为四角哈希的差分基。
```

**携带导数是后文"解析法线"（§6.2）的前提**：法线不是差分近似的，而是与位移
同一个场的精确梯度，这保证了"位移的形"与"光照的明暗"一致。

### 3.2 FBM、旋转与脊线噪声

FBM（分形布朗运动）按 `ampᵢ = 0.5ⁱ` 叠加，频率用矩阵 `M = [[1.6, 1.2], [−1.2, 1.6]]`
推进。`det M = 1.6² + 1.2² = 4.0`，即每倍频**面积 ×4、线频率 ×2**——标准 lacunarity
2.0，同时矩阵自带旋转，避免各倍频格网对齐。此外整个域在第一倍频前先做一次固定
旋转 `fbmRotate()`：值噪声的等值线是"圆角方块"，不旋转时主导倍频会把**轴对齐的
矩形斑块/明暗条带**直接印进地形（迭代日志中实测并修复）。

脊线噪声（ridged）用于山脉：

```
r = 1 − |2n − 1|,  贡献 = amp · r²
```

`|·|` 在噪声过 0.5 处形成 V 形折谷，平方锐化脊线。**`r²` 的导数需带上 `sign(s)`**
（`s = 2n−1`），否则法线在脊线两侧方向错误（`noise.glsl: ridgeFbmd`）。

### 3.3 域扭曲（Domain Warping）

低频扭曲把"以格网为参考系的场"变成"以噪声为参考系的场"：

```
warpX = fbm₃(1.2nx, 1.2ny) − 0.5        （nx, ny = 归一化格坐标）
warpY = fbm₃(1.2nx + 5.0, 1.2ny) − 0.5
wx = nx + 0.22 · warpX,   wy = ny + 0.22 · warpY
```

原理：对查询点先做低频扰动再查表，等值线的形状由"扰动场的等值线"与"目标场的
等值线"复合，原本可能贴格的轮廓被系统性推移。**扭曲的尺度必须小于其特征波长**，
否则会产生自相交式的折叠噪声；0.22 的振幅对应约 1/4 个大陆特征宽度，是安全区间。

### 3.4 大陆与高度场（`mapgen.ts: generateMap`）

陆块判据是一个多通道加权和（阈值 0）：

```
landMass = 0.52 · continent(fbm₅, 频率2.0)
         + 0.14 · elevNoise(fbm₄, 频率4.0)
         + 0.10 · spineMix
         + 0.50 · edge − 0.42
```

其中 `edge` 是到图边的软衰减：`edge = max(0, (d_edge − 0.06)·2.8)^1.2`，让外圈
约 25% 的区域趋势为海。`spineMix = max(0.9·spine, 0.45·spine2)`（两个不同 seed、
不同频率的脊线噪声）让山脉只出现在局部脊线，而非全图隆起。

陆地高度：

```
e = 0.15 + 0.30·elevNoise + 0.40·max(0, landMass)
e += max(0, spineMix − 0.48) · 1.05        （脊线抬升，形成主山脉）
e = clamp(e, 0.08, 1)
```

数据要点：**高度场不是一次噪声**，而是"基底噪声 + 大陆权重 + 脊线脉冲"的合成，
三者频率错开（4.0 / 2.0 / 2.8&4.2），使低地平缓、山地集中在脊线附近。

### 3.5 岸线缓坡：BFS 距离 + 平滑重映射

`ELEV_SCALE = 4`（1 单位 elev = 4 世界单位）下，若临水格仍保持自身高度，海岸会
成为环绕每块陆地的悬崖环。处理不是"削平临水格"（会产生平台阶梯），而是**用
六边形 BFS 距离场做平滑重映射**：

```
① 以所有水格为源做多源 BFS → shoreCells[i] = 到最近水格的 hex 步数
② t = clamp((d − 1)/2, 0, 1)
③ elev *= 0.30 + 0.70 · smoothstep(t)      （t²(3−2t)，C¹）
```

数据原理：BFS 给出**格网上的图距离**（整数），再经 `smoothstep` 映射为 C¹ 连续
的权重——离散距离承载"带宽语义"（近岸 2 格内），连续映射承担"视觉梯度"。
`0.30` 的下限保证近岸不是绝对平台，山体入海时仍能收束成海崖。

### 3.6 生物群系：连续场 + 阈值分类 + 多数滤波

湿度/温度是低频连续场（频率 1.8/1.4 的 FBM），海岸带 `+0.25`、低海拔 `+0.1`。
分类是**在连续场上取阈值**（Mountains: `elev>0.65`；Desert: `aridBelt<0.4 ∧
moisture<0.36 ∧ temp>0.42`……），然后做一轮 6 邻**多数滤波**消除椒盐噪声——
注意滤波只允许改 `terrainId`，不改任何连续场，否则会把阶梯重新引入。

**森林是本文的一个重要数据决策**：`forestCover ∈ [0,1]` 连续存储
（`forestBelt·0.55 + moisture·0.45 + moistBoost`），`featureId`（离散森林标志）
仅在 `cover > 0.45` 时作为 UI 语义写入，**渲染完全不消费 featureId**。随后做一次
去椒盐：6 邻中森林邻居 `≤1` 的格 `cover := 0`；刻意**不做**向 0/1 两端的吸附
（保持场在 (0.05, 0.95) 内连续），因为两端吸附会在林缘重新造出等值线阶梯。

### 3.7 河谷：图上贪心下行 + 距离场

河流生成是格网图上的**最陡下降游走**：

1. 种子：`elev < 0.28 ∧ moisture > 0.55` 的湿地低地，按湿度降序取至多 6 条；
2. 每步在 6 邻中选 `elev` 最小者（禁止回头），走 8–20 步或入海终止；
3. 路径格 `elev ×= 0.72`、邻格 `×= 0.85`（雕刻出谷）；路径格标 `Riverbank`；
4. 以路径为源做 BFS（上限 6 步）→ `riverDist = min(d, 6)/6 ∈ [0,1]`，
   打包进数据纹理 R 通道（陆地区域），供着色器画湿润河岸带与水色缎带。

数据原理：与岸线相同——**路径是离散的（游玩语义：河岸格），但它派生的距离场是
连续的（渲染语义）**。BFS 距离再做 `/6` 归一化，保证不同 seed 下带宽一致。

## 4 数据的表示：打包、预滤波与距离场

### 4.1 通道打包

CPU 侧每格 8 个标量，打包为两张 RGBA8 纹理（`HexMap.packMapTextures`，
`MAP_SUB = 4`，即 40×32 格 → 160×128 texel）：

| 纹理 | R | G | B | A | 预滤波半径 |
|------|---|---|---|---|------------|
| `uMapTex0` | terrainId/8 | featureId/8 | elev | moisture | AREA (2.2 格) |
| `uMapTex1` | 水:shoreDist / 陆:riverDist | forestCover | **有符号岸距** | neighborElevRange | R 用 BAND (1.8 格)，G/A 用 AREA |

着色器对每张纹理**只做一次双线性 tap**（对比：此前 19 格高斯循环需要 19 次手工
采样）。把"滤波"从运行时循环搬到烘焙期，是本系统最重要的性能-质量权衡。

### 4.2 为什么"每格一个数"必然画出六边形——零阶保持与预滤波

把每格标量直接交给 GPU（无论按格常量着色，还是每格 7 顶点插值），渲染的是
**六边形 Voronoi 域上的分段常数函数** `f₀`。任何单调映射（调色板、高度→色带）
的等值线都是域边界——六边形轮廓。这就是迭代日志中反复出现的"马赛克/格印"的
信号处理本质：**数据自身的频谱在六边形格频率上能量无限，渲染侧无论怎么混合都
只是对 f₀ 插值，等值线只能沿格边**。

修法在数据侧：**卷积预滤波**。对每个子格采样点 p（每格 4×4 个），以世界距离
`d`（单位：格距 `√3·HEX_SIZE`）对邻域格加权平均：

```
W(d) = (1 − d/r)³          d < r；否则 0
value(p) = Σ W(dᵢ)·cᵢ / Σ W(dᵢ)
```

选 `(1−t)³` 而非高斯或盒式核的关键：**核及其一阶导在支撑边界 d=r 处同时为 0**。
当某个邻格随 p 移动进出支撑时，其权重从 0 平滑地进出，混合结果 C¹ 连续——不会
出现"采样集合整体换格"造成的阶跃（迭代日志实测：7 格高斯核在换格时跳变 1461×
格内步长；19 格核残留 22×；B 样条/紧支撑核为 0）。 AREA 半径 2.2 格 ≈ 覆盖环 2
邻域，BAND 半径 1.8 格用于岸/河距离带（过强会把泡沫线糊成宽架）。

预滤波后的场在格内也有变化（不再平台），于是等值线脱离格边成为有机轮廓。
`packMapTextures` 的注释记录了一个反例教训：曾尝试"细场 − 粗场"的双尺度增强，
结果格边 rim 差从 +0.02 恶化到 +0.13——因为细粗相减本身又是格对齐结构，增强它
等于把滤掉的频率重新放大。

### 4.3 有符号岸距场：把"海岸"变成可查询的度量

迭代中期最有价值的一次数据结构更换：把 `uMapTex1.B` 从"逐格水位标志/逐格深度"
换成**有符号线段距离场**（`HexMap.shoreSegments / shoreDistance`）：

```
① 收集所有水-陆共享边：每条边是线段 [a,b] 带外法线 n（指向海）
② 对任意查询点 p：
   t  = clamp( dot(p−a, b−a) / |b−a|² , 0, 1 )     （点到线段的垂足参数）
   d² = |p − (a + t(b−a))|²
   sign = +1 若 dot(p − 最近点, n) ≥ 0（海侧），否则 −1（陆侧）
③ sd = sign · √d² ，归一化：texel = 0.5 + 0.5·clamp(sd / SHORE_RANGE, −1, 1)
   SHORE_RANGE = 2.5 世界单位（≈1.44 个 hex 步）
```

为什么距离场在数据原理上全面优于逐格标志：

1. **C⁰ 连续且处处可微（除脊点）**：等值线 `sd = 0` 就是精确水线，不再依附格边；
2. **携带度量**：任何"带宽"（湿沙带、碎浪带、深度梯度）都能写成 `sd` 的光滑
   函数，且带宽以世界单位定义，跨分辨率/跨 seed 一致；
3. **可与噪声复合**：`sd + coastN(p)`（2–3 格尺度的低频扰动）让水线蜿蜒偏移，
   而 8-bit 纹理的量化步长 `2·2.5/255 ≈ 0.02` 世界单位，远小于扰动幅度，不构成
   可见阶梯；
4. **一次烘焙多方消费**：水位遮罩 `waterMask = smoothstep(−0.07, 0.07, sd+coastN)`、
   三段水深色、湿/干沙双带、离岸碎浪带全部读同一个通道，保证它们**彼此对齐**
   （都过同一条水线），不会出现色带互相错位的"拼贴感"。

### 4.4 8-bit 量化的预算

RGBA8 意味着每个通道 256 级。通道分配时必须做量化预算：

- `terrainId/8`：8 类 → 级差 32/255，双线性插值会在类间产生中间值，因此着色器
  用**三角窗权重** `max(0, 1−|tid−k|)` 做软分类而非硬阈值——中间值恰好成为两类
  的混合权重；
- `elev/moisture/forestCover`：0..1 连续 → 步长 1/255，远低于可感知阈值；
- 有符号岸距：见上，0.02 世界单位/级。

## 5 几何的焊接：让水密性与连续性并存

### 5.1 焊接高度场（`terrainContinuity.cellTopY`）

每格顶面由 7 顶点扇形构成。若格心用自己的 elev、角点用邻格的，格面就是"帐篷"。
规则：

```
陆地格顶高 = (自身 elev + 陆地邻格 elev 均值) · ELEV_SCALE   （无条件平滑）
水格恒为 WATER_Y = 0.02（共面海面）
```

数据原理：这是对离散格数据的**紧支撑均值平滑**（7 点盒滤波）。它把"每格一个
标量"的阶梯信号变换为 C⁰ 连续的高度场，是剖面连续性的第一层保证。历史上这里
曾有"按局部落差回插原始高度"的保护项（keep），用于在崖墙机制下保留台地陡缘；
地形连续性规格确立后该项被移除——陡峭地形现在只以连续陡坡存在。

### 5.2 角点规则：无条件焊接（崖墙机制的退役）

一个世界角点由 3 个格共享（`hexesAtWorldVertex` 按**世界坐标几何查询**）。现行
规则只有一条：

```
cornerTopY = mean(cellTopY(共享格集合))        （临水角点 → WATER_Y 岸缘规则）
```

历史机制与本规格的关系值得完整记录，因为它是一次典型的"需求变更驱动的数据
结构退役"：

- 旧机制：三格高度跨度 ≥ `CLIFF_DROP` 的角点按两侧分裂（吸附到 lo/hi）， mesher
  沿分裂边发射垂直侧壁桥接两级台地，以此表达 Civ/Humankind 式的悬崖。
- 失效原因：垂直墙在竖直剖面曲线上是一个**跳变**（坡度→∞），直接违反"任意切面
  必须连续平滑"的规格；同时分裂角点使世界角点携带两个高度，是一切焊接复杂度
  （两侧性、半分裂三角墙、weld 标量分层均值）的根源。
- 退役后：角点单值 ⇒ 相邻格扇形**共享同一批边缘顶点**，曲面天然水密、天然连续，
  无需任何桥接几何。陡崖观感由连续场承担：格间均值 + 连续位移噪声把落差摊开成
  陡坡（实测最大坡度 ≈0.86，约 41°），着色侧以坡度驱动的岩/雪掩模表达岩壁。
- 门禁侧：`profile:check`（`scripts/profile-probe.ts`）以 0.01wu 步长对 4 条贯穿
  剖面线采样，断言最大单步高差 < 0.05wu（实测 0.0086，纯坡度项）——把规格钉成
  机器可验证的不变式。`CLIFF_DROP` 等常数保留导出仅供旧门禁读取，mesher 不再
  消费。

### 5.3 顶点一致性与水密性

无墙之后，水密性来自更强的条件：**同一世界角点在全网格只有一个高度、一组位移
输入**。实现上仍需处理两件事实：

1. 共享角点由每个属主格各发一份顶点，浮点末位可能不同（不同 chunk 的局部和）；
   高度单值性使拷贝间的位置差只剩 ~1e-6 世界单位的浮点噪声，远低于任何可分辨
   缝隙（`crack:metric` 按 1e-4 分组报告 `crackGroups=0`）。
2. 地图边界处的角点可能只属于一个在图像素格（`hexes.length===1` 回退到自身
   高度）——这只发生在界外格不参与网格的情形，不存在第二份拷贝，故无裂缝。

位移一致性不变式（`dispW`）不变：位移输入要么是按世界位置查询的 welded 标量，
要么乘上"仅依赖世界位置"的门控 `dispW`，同一位置的所有顶点拷贝位移一致
（`disp:weld`：2557 个共享位置，0 撕裂；全焊接后 `undisplacedAmpSpan` 从 0.76
降至 0——连水角拷贝也完全一致）。

### 5.4 脊线位移的各向异性域（本轮改动）

山体位移原为各向同性 `ridgeFbmd(p·0.45)`，各倍频叠加后呈"蠕虫团"状。改为
**固定 30° 旋转下的各向异性域**：

```
rp = R(30°) · p,  R = [[0.866, −0.5], [0.5, 0.866]]
q  = rp ∘ (0.32, 0.55)                    （x' 方向频率更低 → 山脊沿 x' 拉长）
Δy = (ridgeFbm(q) − 0.32) · 0.48 · mtnW · uElevScale
```

同一公式以三条路径存在并必须逐常数一致：顶点位移（`hexTerrain.vert.glsl`）、
片元解析法线的链式法则（§6.2）、CPU 拾取副本（`terrainContinuity.displaceLandY`）。
片元侧梯度按雅可比转置传播：

```
∂V/∂p = Jᵀ · ∇qV,   J = diag(0.32, 0.55) · R
∂V/∂x = 0.866·0.32·V_qx + 0.5·0.55·V_qy
∂V/∂z = −0.5·0.32·V_qx + 0.866·0.55·V_qy
```

漏乘 `mt`（矩阵转置链）或漏域旋转会让"法线所属的场"与"位移的场"不是同一个场，
表现为主观上的"轴对齐明暗条带"（迭代日志 sx 条目的实测结论）。

## 6 着色层：从数据纹理到像素

### 6.1 权重化：消灭硬阈值

片元内一切"按格属性开关效果"的分支都改写为**平滑权重乘性叠加**：

```
waterMask = smoothstep(−0.07, 0.07, sdW + coastN)     （水线）
sandW     = max(0, 1 − |tidS − 2|)                    （软分类）
coverAmt  = smoothstep(0.18, 0.82, forestW + 噪声扰动) （林缘）
```

原理与 §4.2 同源：硬阈值在连续场上画等值线，等值线若与数据格边有任何相关就
暴露格结构；权重化让每个效果都是一个连续遮罩，遮罩之间的过渡即是观感。
数据域扭曲（`warp+warpFine`，振幅 0.46+0.24 格）进一步把查表点偏离格坐标，
让生物群系斑块**形状**脱离六边形轮廓。

### 6.2 解析法线与"双计"控制

顶面法线完全来自位移场的片元解析梯度（顶点只位移，不产法线）：

```
n = normalize(vec3(−dHx·0.70, 1, −dHz·0.70))
```

三个来源逐项与位移公式对齐：微观 FBM（`p·1.1`，`mMicro` 含 `landAmp` 权重）、
各向异性脊线（§5.4 的链式法则）、脊线细节（`p·0.55`）。两个实测教训：

1. **顶点插值法线不可用**：每格扇形内顶点梯度是常数，跨格插值在格边撕裂
   （灰底 A/B 实验：ROI 平均梯度 0.00016，纯平）；
2. **法线不能全额放大**：位移已经产生真实起伏，法线再以全强度重建同一梯度是
   "双计"，山体呈脑纹状。0.85 → 0.70 后形与光影重新匹配（本轮实测）。

### 6.3 连续剖面的陡坡着色（崖墙退役后的表达）

崖墙机制退役后（§5.2），"陡"完全由连续场承担，着色层需要回答：没有垂直面，
陡坡如何读作"岩石的陡"而非"拉长的草坡"？现行方案全部建立在连续场上：

1. **坡度驱动**：`slope = 1 − n.y` 来自位移场的片元解析法线（§6.2），是连续量。
   岩石/碎石/雪线掩模都以 `smoothstep` 挂在坡度与海拔上——陡处出岩、缓处出草、
   高处出雪，掩模之间无边界线。
2. **层理随高度**：`rockStrata` 的层理坐标 $b = 3.0\,y + 3.2\,\text{fbm}(p)$——
   层理面是畸变后的水平面等值线，在陡坡剖面上呈厚波状条带（对齐参考图
   `humankind-cliffs-plateaus` 的少量厚层理，而非细直"木板"）。
3. **接触变暗**：`cliffContact = (1 − n.y) · gReliefW`（ neighborElevRange 场），
   连续压暗陡坡的坡脚，替代旧墙的"崖脚暗部"。

值得保留的一课是崖墙机制退役前的最后一轮修复所揭示的机制：曾尝试用混合高度场
的梯度 $\hat N = -\nabla H/\|\nabla H\|$ 作为崖壁法线（对预滤波 elev 纹理做中心
差分），以消除逐边常数法线沿崖墙产生的"折纸/手风琴"明暗方波（两种六边边朝向
受光 3:1 交替）。该修复在数学上成立——*分段常数的任何量（此处是光照输入）都会
把镶嵌图形画进画面*——但在"剖面必须连续"的新规格下，垂直面片整体消失，法线
问题随几何一起退役；其原理已并入 §4.2 的一般论述。同理退役的还有墙面冲蚀沟壑
噪声、`wallT` 深度-达-顶缘渐变、破碎顶缘悬边等墙面专属层。

### 6.4 水体：一个距离场驱动的完整剖面

全部水效果由 §4.3 的 `sdW` 驱动（+噪声扰动）：

```
depth      = clamp(0.95·sdW + fbm 扰动, 0, 1)
water      = 三停色：接触暗带 (0.10,0.26,0.30) → 浅滩青 (0.22,0.50,0.55) → 远海 navy (0.04,0.13,0.32)
caustics   = fbm(p·3.0)·fbm(p·5.0)，浅水权重 shallowW，提升 0.12
surf       = 以 |sdW − (0.08+0.05·noise)| 为带宽的碎浪环，混色 0.22
contact    = 水线前半格压暗 0.7，避免"岸线最亮"的白线效应
```

跨岸亮度剖面曾用约 7500 个水线穿越点做定量验收（`rimAboveBoth ≤ 0.01` 判无亮
边）；白色泡沫叠加（贴岸 albedo 提亮）被 A/B 实验证伪后彻底移除——**浅水的
"白"必须来自水体色阶本身，而不是叠加一层粉刷**。

### 6.5 光照、雾与调色

光照为多叶模型：主 diffuse（`ndlWall = max(ndl, 0.24·wallLift·wallOpen)` 给背光
崖面暖色下限）、wrap、半球环境（墙面地面反弹占 80%，因为 `uSkyColor` 高饱和蓝
会把岩层染青）、树冠透射、菲涅尔天空反射（水面）。雾为指数消光
`1 − exp(−d·ρ·h(y))`，密度 0.006——曾实测 0.013 时把整图地形 luma 均值抬高 56、
对比度砍 45%（"面纱"），降到 0.006 后保留空气透视而不洗白。最终 grade：filmic
tonemap → γ0.96 → 饱和度 1.16 → 软 S 曲线 → 按亮度冷暖分离。

## 7 验证方法学：把"无缝"变成不变式

视觉迭代最大的风险是**回归**与**自欺**（"看起来好了"）。本仓库以五个门禁把
每类失效模式变成可测断言（`npm run p0:check && npm run pick:check`，本轮全绿）：

| 门禁 | 失效模式 | 原理 | 本轮实测 |
|------|----------|------|----------|
| `crack:metric` | 顶面扇形间属性裂缝 | 枚举全部共享角点，按焊接规则断言同组同值 | `crackGroups=0`；全焊接后 `walls=0`（不再有墙） |
| `profile:check` | 剖面高度突变 | 4 条贯穿剖面线按 0.01wu 采样，断言最大单步高差 < 0.05wu | 最大 0.0086（坡度 0.86，≈41°，无跳变） |
| `corner:check` | GPU 位移撕裂 | 读**真实上传顶点缓冲**按位置分组，断言位移输入一致或被墙桥接 | `tornWeightCorners=0`；`maxCpuYSpanAtSharedCorner=0`（此前有崖时 1.64） |
| `hole:check` | 透天洞 | 纯品红天空 + 8 连通封闭区域 + 3×3 腐蚀去 AA 假阳性 + 隐藏 chunk 合成正控制 | `totalHolePixels=0`（合成洞 19.6 万 px 可检出；无墙网格仍水密） |
| `disp:weld` | 位移撕裂 | 读完整网格按三维位置分组断言位移输入一致 | 2557 共享位置 0 撕裂；`undisplacedAmpSpan=0`（此前 0.76） |
| `pick:check` | 拾取与画面脱节 | CPU `heightAt` 精确复刻 mesher 扇形；射线步进+二分 vs GPU 采样 | 面上误差 max **1.37e-7**（有崖机制时 1.08——分裂角点曾是 CPU/GPU 失配主源），同格率 87% |

方法学要点（都来自真实的假阳性教训，见日志）：

- **检测器自身要验证**：hole 检测曾把抗锯齿过渡行判成天空（879 假阳性），修复
  靠"纯品红天空 + 腐蚀 + 合成正控制"三件套——没有正控制的"0 缺陷"不可信；
- **门禁读真实数据**：corner/disp:weld 读 GPU 上传后的字节，而不是重新实现一遍
  CPU 逻辑去对比 CPU 逻辑；
- **浮点分组按毫单位整数**，避免 `(−1e−17).toFixed(3) === '-0.000'` 一类把同一
  角点拆成两组的假阳性。

## 8 讨论与展望

**残留限制**。游玩数据终究是每格一个样本：预滤波让场的**值**连续，但信息的
空间分辨率仍是格级——极近景下，大尺度斑块（森林团块、浅水架）的形状仍受格
数据约束（这正是 P2 提出"每格 4×4 子样本烘焙"的动机，目前 4×4 只用于滤波
采样点密度，源数据仍是每格 1 值）。CPU 拾取副本与 GPU 噪声的哈希实现不同
（JS double sin-hash vs GLSL highp fract-hash），山体上的拾取精度受此限制
（同格率 88%，门限 75%）——彻底修复需要把 GLSL 哈希逐位移植并用 float32
模拟，收益低。

**数据原理层面的后续方向**：

1. **子格源数据**：把 `forestCover/elev` 在烘焙期做分形上采样（格值作为低频
   系数，叠加格内高频 FBM），使信息分辨率与 texel 分辨率对齐；
2. **河面几何**：riverDist 场已具备把河道升为真实水面的全部信息（宽度=距离场
   等值线，高度=WATER_Y），可复用岸距 SDF 的整套水着色；
3. **位移与数据的统一**：现在 elev（数据）与位移（噪声）是两个场的叠加，雪线
   因此依赖 CPU 位移探针标定（`calib-y.ts`）。若把位移场烘焙回 elev 场，所有
   高度语义（雪线、拾取、AI）共享一个真源。

---

## 9 结论

Hexbound 的经验可以压缩成三条数据原理：

1. **语义分层**：离散（格、地形类型、特征标志）只服务游玩与 UI；一切进入渲染
   的量必须是连续场。两者之间用"距离场 + 平滑映射"转换（BFS 距离→smoothstep、
   线段 SDF、河距归一化）。
2. **滤波在数据侧**：渲染侧的混合只能插值数据已有的频率；六边形马赛克要在
   烘焙期用紧支撑核预滤波消灭，核在支撑边界处 C¹ 归零以保证采样集切换无阶跃。
3. **一致性做成不变式并机器验证**：几何焊接、位移门控、CPU/GPU 副本共享同一
   组公式与常数，并用读真实顶点缓冲的门禁持续验证——"无缝"不是一次性的视觉
   调参结果，而是被测试钉死的系统性质。
