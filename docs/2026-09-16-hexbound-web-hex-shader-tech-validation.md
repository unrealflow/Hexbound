# Hexbound 网页版 — 六边形地形纯 Shader 图形技术验证方案

- 版本：v0.1  
- 日期：2026-09-16  
- 状态：技术验证方案（非完整游戏设计）  
- 上游设计：Hexbound 设计方案 v0.4（探索层地形/地表双层、pointy-top 轴坐标）  
- 平台变更：**放弃 TapTap Maker / UrhoX** → **本地网页**（浏览器打开即可）  
- 验证目标：在网页中实现可交互的六边形大地图地形观感；**不同地表须有可辨识的真实感表现**；**禁止使用外部模型与贴图资源**（含无程序生成的 albedo/normal 图）。

---

## 0. 一句话结论

**底座选 Babylon.js（WebGL2 优先，WebGPU 可选开）+ 分块六边形网格几何 + 数据驱动顶点属性 + 单一（或少数）程序化地形 Shader。**  
几何只表达「六边形棱柱/台地」；水、林、山、冰、沼泽等外观全部在 Shader 里用噪声、SDF、分层着色与动画完成。

## 2. 引擎选型

| 候选 | 结论 |
|------|------|
| **Babylon.js** | **采用**。自定义 `ShaderMaterial` / Node Material；正交相机、拾取、GUI 调试面板成熟；后续可接 WGSL。 |
| PlayCanvas | 可用，但验证阶段编辑器非必需；代码驱动地形生成用 Babylon 更直接。 |
| three.js | 可行，但 WebGPU 自定义 shader 路径偏 TSL；本验证要「手写程序化材质」时 Babylon `ShaderMaterial` 更直。 |
| 自写 WebGL | 成本过高，不适合「先验证再接玩法」。 |

**运行时**：Chrome/Edge 本地；构建用 Vite + TypeScript。  
**着色语言**：首期 **GLSL ES 3.00（WebGL2）**；结构预留 `#ifdef WEBGPU` / 平行 WGSL 文件（二期）。

## 3. 几何与数据架构（无模型资产）

### 3.1 原则

- **唯一几何原语**：程序生成的六边形柱/台（顶面 + 可选侧面）。  
- **不加载** mesh 资产；运行时用 `VertexData` / 自写 typed array 建 Buffer。  
- 外观差异 **不靠换模型**，靠顶点属性 + Shader 分支/混合。

### 3.2 坐标系

- **pointy-top**，**轴坐标 (q, r)**，`s = -q-r`。  
- 世界坐标：

```
x = size * √3 * (q + r/2)
z = size * 3/2 * r
y = elevation * elevScale
```

- `size`（外接半径）与设计稿探索格一致即可（验证用常量，如 1.0）。

### 3.3 分块（Chunk）

- Chunk 尺寸建议 **8×8 格**（对齐原 UrhoX 方案意图）。  
- 每 Chunk：**一个** `Mesh` + **一个** 地形 `ShaderMaterial` 实例（或材质共享 + 不同 uniform 块；首期共享 Shader，per-chunk 少 uniform）。  
- 60×40 → 约 8×5 = 40 个 draw call 量级（仅地形）。  
- Chunk 重建触发：迷雾/调试改地形时按脏矩形重建（验证期可整 chunk 重建）。

### 3.4 单格网格拓扑（推荐）

每种格挤出为矮棱柱：

- 顶面：中心 + 6 顶点（或细分 2～3 环，供山地/水体顶点动画）  
- 侧面：6 个四边形（山脉/丘陵露出岩层；水域侧面可半透明）  
- **不做** 独立树/石子 mesh  

可选简化（更快出片）：**仅顶面扇形 + 忽略侧面**，山地靠顶面位移与边缘陡色带「假侧面」。验证 **M0a 仅顶面**，**M0b 加侧面**。

### 3.5 顶点属性（数据驱动）

| Attribute | 类型 | 含义 |
|-----------|------|------|
| `position` | vec3 | 局部/世界位置 |
| `normal` | vec3 | 初始法线（Shader 内可重算） |
| `hexCorner` | float / vec2 | 角向 0～5 或顶面 UV 极坐标 |
| `terrainId` | float | 基础地形枚举 |
| `featureId` | float | 地表特征枚举 |
| `elev` | float | 高程 0～1（丘陵/山） |
| `moisture` | float | 湿度（沼泽/雨林） |
| `edgeMask` | float | 邻接水域/道路等边界因子 0～1 |
| `ao` | float | 预计算简易环境光遮蔽（可选） |

**CPU 侧**仍持有 `HexMap` 逻辑格数据（移动消耗等可后续接）；GPU 只吃烘焙进 chunk 的属性。

### 3.6 枚举与设计稿对齐（验证子集可裁）

**terrainId**：平原、草原、沙漠、冻土、丘陵、山脉、浅水、深水（海/湖）。  
**featureId**：无、森林、雨林、沼泽、沙丘、道路、绿洲、河流边。  

验证必须做出可辨识差异的集合（最低集）：

1. 平原 / 草原  
2. 沙漠 + 沙丘感  
3. 森林  
4. 山地（丘陵→山脉过渡）  
5. 水面（含岸线）  
6. 冰面或冻土  
7. 沼泽（可选加分）

## 4. 纯 Shader 地表表现方案（核心）

### 4.1 总策略

- **禁止** `sampler2D` 采样图片贴图。  
- **允许**：  
  - 程序噪声（Value / Simplex / FBM / Worley）  
  - 解析 SDF（圆、胶囊、六边形距离场）  
  - 屏幕空间近似（Fresnel、假反射：采样场景色或天空色渐变）  
  - 时间 `uTime` 做动画  
- **一个主 Shader** `hexTerrain.frag` + `hexTerrain.vert`；用 `terrainId/featureId` 混合，避免 10 个材质切换。

伪结构：

```
albedo, roughness, metal, emissive, alpha, normalTS =
  mix layers by terrainId/featureId
+ procedural detail (noise, SDF)
+ edge effects (shore foam, snow line)
```

### 4.2 顶点阶段（vert）

| 效果 | 做法 |
|------|------|
| 丘陵/山体 | `pos.y += f(elev, noise(q,r))`；山脉加强位移与陡峭 |
| 水面 | 顶面顶点 `y` 用低频正弦 + 噪声做波高（幅度小） |
| 风吹草/林冠暗示 | 顶面水平微偏移（仅草原/森林 feature，幅度随 `uTime`） |
| 法线 | 位移后在邻域差分或解析波函数求 `normal` |

### 4.3 各地表 Fragment 设计（无贴图）

#### A. 平原 / 草原

- 底色：黄绿～翠绿 `mix`，由 `moisture` 与低频噪声调制。  
- 草感：**没有草模型**；用 **各向异性高光条带** + 高频噪声暗点模拟草丛密度；视角掠射时 Fresnel 提亮。  
- 可选：基于屏幕导数的「假毛发」暗线（廉价）。

#### B. 沙漠 / 沙丘

- 暖黄沙色 + Worley/FBM 做出沙波纹（`sin(dot(xz, dir) + noise)`）。  
- 沙丘：`elev` 驱动亮暗坡向（朗伯 + 强对比）。  
- 热浪（可选）：片元对 UV/`worldPos` 做轻微时域扭曲（仅远景 alpha 区）。

#### C. 森林 / 雨林（重点）

**不种树模型**，用「冠层体积暗示」：

1. **冠层密度场**：Worley/FBM → `canopy` 0～1。  
2. **分层色**：深绿冠、中绿过渡、近地褐（由 `canopy` 与视角仰角混合）。  
3. **树干暗示**：稀疏竖直条带 SDF（`fract` 格内局部坐标），暗色、低密度，仅近距离（`fwidth` 控制）。  
4. **孔隙透光**：冠层噪声洞中透出地面色。  
5. **雨林**：提高 `moisture`、加雾感（距离雾偏绿）与稀疏「垂藤」竖线。  
6. **风**：`canopy` 采样坐标随 `uTime` 微移。

远景只保留冠层色斑；近景加强竖线与孔隙——用 `cameraDistance` LOD。

#### D. 山地 / 山脉

- 顶点强位移 + 侧面（若有）岩层色带：`floor(pos.y * bands)` 分层。  
- Fragment：坡度 `1.0 - normal.y` → 陡处灰岩、缓处覆草/雪。  
- 雪线：`elev > snowLine` 变白，噪声破边。  
- 岩石感：高强度 FBM 做裂纹暗缝（非贴图）。

#### E. 水面（浅水 / 深水）

- **颜色**：Beer–Lambert 式深度着色（深水更墨蓝；浅水透底色）。底色来自邻格陆地色（CPU 写入 `edgeMask`/岸色 uniform 或顶点色）。  
- **波**：双层 Gerstner/正弦近似或噪声法线；高光 Blinn。  
- **岸线泡沫**：`edgeMask` 与噪声 → 白边脉冲。  
- **反射**：简化环境色（天空梯度）+ Fresnel；验证期不做真实 SSR。  
- **透明**：浅水 `alpha &lt; 1`，深水近乎不透明。  
- **河流**：窄带浅水 + 沿流向的各向异性高光（流向由 CPU 写入 `flowDir` 属性，可选）。

#### F. 冰面 / 冻土

- 高粗糙度对比：裂纹用 Worley 暗线；强 Fresnel 冷色高光。  
- 冻土：低饱和蓝灰底 + 稀疏冰斑混合。  
- 火融冰（玩法二期）：验证期可只留外观，留 `melt` uniform 接口。

#### G. 沼泽

- 浊绿水面 + 高浑浊（降低透射）。  
- 斑驳「浮岛」：噪声阈值陆地色。  
- 薄雾：相机距离雾 + 局部噪声 alpha（假体积）。

#### H. 道路 / 绿洲

- 道路：压低噪声、灰褐条带、略亮；覆盖森林密度。  
- 绿洲：局部高 moisture 绿地 + 小范围清水色（可用 feature 覆盖）。

### 4.4 照明与大气（仍无贴图）

- 单方向光 + 半球环境（天空/地面色常量）。  
- 距离雾（按地形调色：沙漠暖雾、沼泽绿雾）。  
- 战争迷雾（二期）：顶点色三态或 chunk uniform；验证可先全亮 + 调试开关「假迷雾」。

### 4.5 性能红线（验证机）

| 项 | 目标 |
|----|------|
| 分辨率 | 1080p 笔记本核显 / 普通独显 |
| 帧率 | ≥ 60 FPS（60×40 全图） |
| 噪声 | FBM 层数远景 2、近景 4；用 `fwidth` 做 mip 式收敛 |
| 透明 | 水域单独排序或近似（先不透明深水 + 浅水小透明带） |

## 5. 模块划分（网页 TypeScript）

```
hexbound-web/
├── index.html
├── package.json
├── src/
│   ├── main.ts                 # 引擎启动、渲染循环
│   ├── scene/
│   │   ├── createScene.ts      # 正交相机、光、雾
│   │   └── picking.ts          # 射线 → 六边形轴坐标
│   ├── hex/
│   │   ├── coords.ts           # 轴坐标、邻居、距离、像素互转
│   │   ├── HexMap.ts           # 逻辑格：terrain/feature/elev
│   │   ├── mapgen.ts           # 种子噪声生成验证地图
│   │   └── ChunkMesher.ts      # 8×8 合并 VertexData
│   ├── render/
│   │   ├── HexTerrainMaterial.ts
│   │   ├── shaders/
│   │   │   ├── hexTerrain.vert.glsl
│   │   │   ├── hexTerrain.frag.glsl
│   │   │   └── noise.glsl      # 共用噪声库（字符串 include）
│   │   └── ChunkRenderer.ts
│   └── ui/
│       └── debugPanel.ts       # 种子、效果开关、刷地形
└── docs/                       # 本方案
```

依赖方向：`coords` 纯函数 ← `HexMap` / `ChunkMesher` ← `ChunkRenderer`；Shader 不依赖玩法。

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 纯噪声森林「像脏斑不像树」 | 近景加竖向 SDF 树干暗示 + LOD；接受远景印象派 |
| 透明水排序 | 深水不透明、浅水窄带；或 OIT 不做，改扭曲反射 |
| 全图 FBM 过重 | Chunk 距离分级；噪声层数随相机高度降 |
| WebGPU 差异 | 首期钉 WebGL2；WGSL 平行翻译放 G5 后 |
| 与玩法耦合过早 | `HexMap` API 稳定，UI/回合一律后置 |

## 11. 决策摘要

| 项 | 选择 |
|----|------|
| 平台 | 本地网页 |
| 引擎 | Babylon.js + TS + Vite |
| 几何 | 程序化六边形 Chunk，无模型 |
| 外观 | 纯程序化 Shader，无贴图 |
| 首期 API | WebGL2 / GLSL |
| 成功标准 | 水/林/山等可辨真实感 + 性能达标 |

**本阶段不是做完整 Hexbound，而是证明：网页上用纯 Shader 能做出「文明式六边形地形」级别的可读、可玩视觉地基。**
